# TASK-0036: Pilot DO-03 — Case Selection System & Level Progression Loop

## 1. Context & Operational Need
Under field problem report `docs/agent-system/problems/Tua_game_nay_dang_co_van_de.txt` (DO-03) and Dupery V1/V3 handbooks:
1. **Case Selection (1-of-3)**: Players must be presented with 3 distinct procedural case options at the start of each round, allowing them to choose which dossier to investigate based on difficulty, regional crime scene, suspect count, and reputation rewards.
2. **Level Progression (Candy Crush / Angry Birds Paradigm)**: The game requires a persistent, star-rated level progression structure:
   - Each level tracks unlocked state, 1-3 star clear rating, and high score.
   - Star evaluation metrics:
     - 1 Star: Solved the case (correct evil identification).
     - 2 Stars: Solved + 0 innocent casualties.
     - 3 Stars: Solved + 0 innocent casualties + solved within par moves.
   - Cascading unlocks: Clearing level $N$ unlocks level $N+1$.
   - Reliable JSON persistence to `user://save/level_progression.json` with corrupt-file fallback.
3. **Clean Architecture Separation**:
   - `CaseSelectionManager.gd`: Pure domain logic.
   - `LevelProgressionManager.gd`: Pure domain logic.
   - `CaseSelectionModal.tscn` & `CaseSelectionModalController.gd`: Pure presentation layer.
